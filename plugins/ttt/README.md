# s2script TTT

Upgrade of `s2s-ttt-port-old` to s2script 0.7.0, SDK 0.27.1 and CS2 0.19.1. The old port supplies the gameplay and visuals. Use public framework APIs and official, unmodified Metamod/KHook suppliers.

Staging currently runs the separately built framework `0.7.0+value-copy.c8140bd885b2`. It removes redundant typed-value serialization and repairs a separate terminal V8 teardown failure. The [build and production handback evidence](docs/evidence/staging/owned-value-transport-2026-10-05.md) records the exact source, artifacts, retained validation fences and bounded timing observations. The remaining role-start hitch and human carry acceptance are open; this deployment does not establish original-monolith performance parity.

The latest [Body and Core observation fix](docs/evidence/staging/body-input-work-2026-10-05.md) avoids constructing guarded Player facades for input and actor identity reads. All671 workspace tests pass. A same-process stopped-bot comparison measured about19% less main-thread CPU with the Body fix; real-client carry and role-start acceptance remain open.

Core owns the registry, round, combat and ordered decisions. Karma, the existing seven special rounds, private Panorama HUD, World visuals, Communication, Shop, Bodies, Reports and Items each have separate archives. Shared source contains pure helpers; feature state has one owner. The catalog retains the old port's21 items.

Build/test tooling requires Node24+ and Python3 for the staging-probe contract preparer. From the repository root, run `npm ci` and `npm run check`. The real SDK CLI builds all ten archives before archive tests run. Install each `plugins/<owner>/dist/_edgegamers_ttt-<owner>.s2sp` for the normal preset; the staging probe is a separate operator tool. Use archives from one build so their Protocol2 declarations match.

Player-facing text uses the s2script translations library. `translations/ttt.phrases.json` is the English phrase set (SDK syntax: `{1}` arguments, `{colour}` tags); each archive bundles it as the built-in default, and every plugin formats locally. Deploy it to `addons/s2script/translations/ttt.phrases.json` to edit wording without a rebuild, and add `addons/s2script/translations/<code>/ttt.phrases.json` (for example `de`) for other languages; players get their `cl_language`, falling back to English per phrase. Core's old `phrases_file` setting is still accepted in config files but ignored with a warning: its `%KEY%`/`%s%`/`%an%` syntax is not the SDK's.

Omitting a feature disables its behavior and retains applicable fallbacks. Without Karma, credit scaling uses its last observed default/minimum (old defaults before first attachment); there are no karma penalties or timeouts. Without Communication, private chat is suppressed until its owner returns. Missing Items refuses the18 grants requiring effects; the three native-only grants remain available. Reports owns the existing per-map report/prompt/debt stores. Core retains native sanctions and consumes a promised private reason safely if Reports disappears.

Core, Karma, Special, Shop, World and Bodies own typed canonical settings and writable legacy ConVar aliases. SDK-generated files use `configs/_edgegamers_ttt-<owner>.json` and support JSONC line comments. The bounded [legacy importer](tools/config/import-legacy.mjs) maps all169 aliases before deployment; the existing Core phrases_file is preserved in the file but no longer read. For an eight-owner installation, explicitly migrate the five old Core body controls offline with `--migrate-body-settings --merge-missing`, inspecting the dry-run receipt before writing. Existing Bodies choices win. [Importer instructions](tools/config/README.md) and [configuration decisions](docs/adr/0008-reports-items-and-body-settings.md) explain precedence and timing.

Panorama uses the existing first-party hudkit with `observable:false`. UI actions carry connection/round identity; Core rechecks purchases and admin access. Player RDM reporting (the victim's yes/no prompt, the bare `!report` picker and every outcome) uses the same hudkit sheets as the shop; only the reason is typed in chat, and chat remains the fallback when the HUD is unavailable ([ADR0013](docs/adr/0013-player-report-panorama.md)). Report selection and ban confirmation also carry the Reports attachment identity. Buddy outlines and corpse behavior remain the existing implementation. Items owns the unchanged current-API HE descriptor and its derived `engine:calls` permission.
