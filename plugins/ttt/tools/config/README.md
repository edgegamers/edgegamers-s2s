# Import existing Core, Karma, Special, World, Bodies and Shop settings

Use Node 24 or newer from this repository. The importer reads existing ConVar assignments as data; it never runs a cfg command.

```sh
node tools/config/import-legacy.mjs --input /path/to/old.cfg --out-dir /path/to/s2script/configs
node tools/config/import-legacy.mjs --input /path/to/old.cfg --out-dir /path/to/s2script/configs --write --receipt /path/to/import-receipt.json
```

The default is a dry run. The JSON receipt lists exact legacy aliases, canonical keys, values, ignored lines, and SHA-256 hashes. Inputs may be cfg assignments (`name value` or `sm_cvar name value`) or a flat JSON/JSONC export of old names and scalar values. Quoted blank `sm_ttt_karma_low_command ""` remains blank. Numeric aliases retain the old parser and clamp policy. Boolean aliases also retain the old parser: `0` or case-insensitive `false` is false; other nonempty strings (including `off` and `false-like`) are true, and blank uses the original default. Flat exports may use actual JSON booleans for boolean aliases only. Unknown commands and names are ignored and listed.

The only outputs are `_edgegamers_ttt-core.json`, `_edgegamers_ttt-karma.json`, `_edgegamers_ttt-special.json`, `_edgegamers_ttt-world.json`, `_edgegamers_ttt-bodies.json`, and `_edgegamers_ttt-shop.json`. The finite inventory contains 20 Core, 5 Bodies, 23 Karma, 11 Special, 3 World and 107 Shop aliases (169 total), including `sm_ttt_dna_glow`. The owner manifests define their schema and defaults; owner `src/settings-specs.ts` files contain the finite alias mapping. Existing canonical files win byte-for-byte by default. Explicit `--merge-missing` fills only absent imported keys and preserves existing values, including malformed/null/scalar section choices. Existing numeric tokens such as `80.0`, `8e1` and `-0` remain unchanged in a merge, so an invalid canonical integer is not accidentally activated by reformatting. Invalid JSON refuses the merge. Back up existing files before this optional offline merge and avoid concurrent editors: writes are individually verified, not a multi-file transaction. A later I/O failure may leave an earlier file written; inspect those files before rerunning. Existing receipt files are never overwritten.

After installation, these canonical files are the only authority. Legacy aliases write through to them after readback verification. Unseen external edits refuse an alias write until the SDK materializes the file. Numeric values promote at the original Core snapshot boundaries; the low-karma command remains live. The SDK accepts line comments, not trailing commas or block comments. Alias writes regenerate the owner file and its comments. No storage connection is activated by importing `databaseConnection`.

Shop import moves existing settings only. Dormant baseline knobs remain dormant; importing their values does not enable a new item behavior, effect or balance rule.

Core preserves its existing canonical-only `phrases_file` field. The field is no longer read: phrase overrides belong in `addons/s2script/translations/ttt.phrases.json` (see the main README). A newly created Core file defaults it to blank; it has no legacy alias, and an existing value is never replaced by imported settings. Translation files still load only at plugin startup. The five body settings are owned by Bodies. For an existing Core canonical file, explicitly add `--migrate-body-settings --merge-missing` to copy those choices into missing Bodies keys before importing aliases. Existing Bodies choices win, then old Core choices, then input aliases. Raw number tokens and malformed section choices are preserved; old Core data is retained. This option requires `--merge-missing` and remains a dry run without `--write`.
