# Public API staging probe

An isolated diagnostic package for stock s2script v0.7.0, published SDK 0.27.1 / CS2 0.19.1. Requires Core 2.x and Karma 2.x. It publishes no interface and has no framework, supplier, binary, or runtime patch dependency. Root owns deployment and the `engine:calls` allowlist for `@edgegamers/ttt-public-api-probe`.

Every command requires server console/RCON (`callerSlot=-1`, `replySource=server`) and exact argument count. The `ttt_public_*` commands additionally require hostname exactly `s2s-ttt-staging`, `sv_lan=1`, and zero connected valid human clients. Bot slots are decimal 0–99 and must resolve to a living, current bot pawn. This package never changes these server settings or adds bots.

`ttt_staging_identity` is a read-only, server-console-only diagnostic with no arguments. It works with public servers and receiving clients present, without changing LAN or hostname settings. It returns only `state`, `epoch`, `roundsThisMap` and at most 64 copied player identities containing `slot`, `generation` and `roundEpoch`. It excludes Steam IDs, names, roles and configuration values, discards a sample if the epoch changes during the read, and reports provider failure without exposing its details. Use it immediately before and after a Core reload to compare stable round and connection identity; existing mutation-probe restrictions remain unchanged.

1. `ttt_public_check`
   - Calls the actual cross-context Core `getGame`, `activeSlots`, registry reads and `hasDomain`; calls Karma `getHandlers`, `karmaOf`, `timeoutRemaining`.
   - Reports `exactKarmaHandlers`, the seven expected handler IDs, copied game/registry/domain values, `heAvailable` and the actual optional binding reason. These are observations, not a claim that callbacks or projectiles have occurred. Empty registry is a legitimate result when Core has not joined bots yet.
2. `ttt_public_watch <bot-slot>`
   - Replaces the single previous observer; installs public `SDKHook(pawn.ref, 'OnTakeDamage', callback)` for at most 60 engine seconds, capped at 16 observations.
   - `registered:true` proves registration returned true. Only subsequent `event:damage` receipts prove the actual callback. Each copies damage, damageType and victim/attacker/inflictor id/index synchronously; no borrowed record is retained, mutated or suppressed.
3. `ttt_public_he <bot-slot>`
   - Explicitly calls the current optional `Engine.function('createHeGrenade')` at that bot's origin +16Z. Exactly three attempts, fixed 120-degree ring, horizontal velocity60 and vertical30; HE definition44, current controller team and retained pawn thrower. Diagnostic geometry is small and fixed, not a replacement for Core Cluster tuning.
   - Reports returned/valid native entity refs. Refuses overlapping rings. Frame-driven cleanup after five engine seconds avoids timer queue admission failure. Existing engine HE fuse may detonate first. A current bot, Core damage policy, engine team/round rules and blast geometry determine whether a damage callback happens; missing callbacks are not synthesized.
4. `ttt_public_cleanup`
   - Requests `Kill` only for refs returned by this probe and removes the observer. Cleanup also runs on map end/unload, loss of retained controller/pawn/connection, or admission of a human. The receipt distinguishes `alreadyGone`, accepted `killRequestsAccepted`, refused inputs and exceptions. An accepted input is not proof of final native removal.

Run watch before HE if measuring real grenade damage. Core hooks may already change or suppress the damage before this observer sees it. A real ordinary bot combat hit can also supply a callback. Published SDK 0.27.1 has no direct `takeDamage`/`applyDamage` API; `Client.fakeCommand` only executes registered console commands, and `kill`/`Pawn.slay` are suicide, not substitutes for ordinary damage. This probe does not invent a native damage injector or require one.

Output is JSON chunk envelopes `{probe,part,total,text}`. Collect all parts for one `probe`, order by `part`, concatenate `text`, then parse the resulting JSON. Each text chunk is at most240 UTF-16 code units; worst escaping stays below the server's2047-byte envelope. No client messages are emitted.

Build from repository root (does not modify workspace metadata):

```sh
python3 tools/staging/public-api-probe/prepare-contracts.py
node_modules/.bin/s2s build tools/staging/public-api-probe
node_modules/.bin/tsc --project tools/staging/public-api-probe/tsconfig.json
node --test tools/staging/public-api-probe/test/*.mjs
node --test tools/staging/public-api-probe/test/*.test.ts
```

`prepare-contracts.py` extracts actual types/publication metadata from the existing Core/Karma CLI archives, verifies their SHA256, and writes only this package's `.s2script/types` cache. The CLI independently verifies metadata hashes and generates protocol-2 associations. It does not create local fake interfaces or broaden the workspace.

Candidate: `dist/_edgegamers_ttt-public-api-probe.s2sp`. See `hashes.json` and `report.md`. Fixture tests replace engine-owned boundary modules around the actual archived JavaScript; they are not live engine acceptance.

`ttt_staging_pawn` is a read-only, no-argument, server-console-only receiving-human diagnostic. It copies native pawn/controller possession, movement/input, render/weapon/native-lock fields and logical alive/participating/shop state, omits bots and private identities, and drops observations retired during reads. It does not acquire a custom camera or modify movement, weapons, HUD or game state. A living `Player.pawn` is compared with actual controller `m_hPawn`, not assumed to be possessed.

`ttt_staging_capture` is a no-argument, server-console-only bounded inspection of each receiving human's physical custom-HUD capture fields. It reuses the existing framework HUD-lab private live-schema resolver and raw read recipe, rather than a public SDK capture getter (none is exposed). It checks every discovered layout, current schema/embedded-state span, vector count, retained native client/map/round/entity lifetime, and emits global/per-player flags separately. State slot mismatch/unallocated/unreadable is unknown; a sequential server copy is not a client acknowledgement. No capture setter, lease mutation, hook or camera acquisition is used. Host capture lease metadata remains unobservable.

`ttt_public_weapon <bot-slot> bare|replace` uses the same bot-only mutation admission. Bare refuses an occupied primary slot and gives one M4A1-S. Replace removes only captured, valid owned pistols and gives one revolver on the next actual PRE. The retained living and actually possessed pawn, connection, map, round epoch/state and installation are checked at effect boundaries. Before, immediately after removal, after grant and seven fixed PRE samples expose inventory/active ownership and grant flags. The operator-only read also records the unnamed pawn byte at0x318 from the audited installed ELF through public `EntityRef.readUInt8`, guarded by liveness before/after and the surrounding native lifetime seals. This fixed offset is diagnostic evidence for that ELF, not a portable schema field or continuous sampler. One ten-second bounded experiment, no retry or destructive cleanup. The corrected SDK reports accepted void dispatch for owned removal; this is not proof that deferred destruction has completed. Earlier receipts used the defective pawn receiver and must not be interpreted as healthy native inventory transitions. These observations do not establish receiving-client movement or rendering.

`ttt_staging_grant_arm` starts one read-only human observation for at most300 wall seconds; `ttt_staging_grant_stop` stops it. Both are server-console-only/no-argument; ARM also requires the exact staging hostname. A reusable Scope is created during plugin load, with subscriptions only while armed. Discovery/light inventory reads occur at most1Hz; the first pickup or inventory change starts a two-second window with at most21 detailed samples at100ms intervals. Other PRE callbacks make no observer native reads. Pickup queues observation for PRE, with no synchronous inventory read. Reads pin one native human connection, controller, player/possessed pawn, provider, map and round epoch, and permit countdown-to-active within that round. Replacement or retirement ends observation. Map end clears subscriptions and permits future rearm; unload closes permanently. No UserCmd detour, camera acquisition, movement/input/weapon writes or private identities. Output excludes the internal inventory signature. Input aggregates are sparse server observations: zero samples do not prove that a receiving client sent no input. The trigger does not establish grant provenance, the prior light sample is not a full pre-grant snapshot, and observer overhead is unmeasured.

`ttt_staging_weapons` is a no-argument staging-console-only copied weapon/inventory/processed-input snapshot for at most64 current clients, without private identities or effects. `ttt_staging_bot_snapshot` reads only living, actually possessed bots. `ttt_staging_bot_motion [slot]` observes one retained living bot for five seconds at most5Hz, reporting distance/path/displacement and active weapon state while retaining private coordinates locally. Empty Scope is allocated at load; subscriptions exist only while observing, with no native queries between due samples. All native connection/controller/pawn/possession, map, provider, probe and round epoch seals remain; death/replacement retires. Same-round phase changes can be observed. No coordinates, entity refs, grants, removals, camera/input writes or UserCmd subscriptions. These server position measurements cannot establish receiving-client rendering or exclude a previous round's freeze.

The [bounded movement operator](fixed-revolver-motion.py) is staging-root-only and inert without `--execute --pins <exact-path-sha256.json>`. It requires zero humans/eight bots, normal original LAN/firing controls, an active complete Core roster, exact deployment pins, a living owned active pistol and current container identity. One guarded replacement is followed by seven PRE observations and five seconds of bot movement reads; it requires a retained owned/active revolver, positive movement and unchanged Core generation/round/process/hash state. Work is bounded to20seconds; cleanup runs separately and always attempts restoration. It temporarily uses stock `sm_cvar bot_dont_shoot` to prevent combat death, with LAN returned to its original value before movement sampling. Receipts/logs are private and receiving-client rendering is always unobserved. The accepted October6 result is recorded in the [removal evidence](../../../docs/evidence/staging/weapon-removal-receiver-2026-10-06.md).
