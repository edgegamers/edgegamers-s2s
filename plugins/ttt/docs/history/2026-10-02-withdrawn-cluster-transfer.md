# Withdrawn Cluster grenade-transfer research

Withdrawn October2,2026 by the user's buyer-only clarification (ADR0009). The current old-port buyer's-next-HE charge is the desired behavior. Grenade-transfer timing observations and the proposal below are retained only as historical research; they are not pending implementation or acceptance prerequisites.

The actual granted Weapon.ref is available from Pawn.giveNamedItem and already returned by Core's inventory helper. Core currently discards it for Cluster. HE detonation supplies entityid, also currently discarded. The projectile exposes thrower/originalThrower refs and item definition, but no source-weapon handle. grenade_thrown supplies only the user and weapon name. Those facts establish useful identities without establishing a physical weapon-to-projectile association. [Grant declaration](https://github.com/s2script/s2script/blob/be0a3e33041e921ec113203d4e14a22c996deab7/packages/cs2/index.d.ts#L138), [weapon API](https://github.com/s2script/s2script/blob/be0a3e33041e921ec113203d4e14a22c996deab7/packages/cs2/weapon.d.ts), [grenade events](https://github.com/s2script/s2script/blob/be0a3e33041e921ec113203d4e14a22c996deab7/packages/cs2/events.generated.d.ts#L424).

Use observeOnly v2 PRE/POST on the already verified HE factory target. POST exposes its genuine returned projectile and thrower argument. Record current active weapon/inventory identities, lifecycle events and detonation order for normal primary/secondary throws, quick switch, death drop and another client's pickup/throw. Also measure granting while already carrying an HE: a returned weapon must not be assumed to represent a separate grenade when the engine merges inventory. [Engine subscription contract](https://github.com/s2script/s2script/blob/be0a3e33041e921ec113203d4e14a22c996deab7/packages/sdk/unsafe.d.ts), [generated v2 fields](https://github.com/s2script/s2script/blob/be0a3e33041e921ec113203d4e14a22c996deab7/packages/sdk/src/engine-functions/emit-dts.ts#L19).

The observer needs its precise engine:hooks allowlist grant and active subscription receipts; function availability alone is insufficient. Keep a fixed actor/map/generation,20-callback/60-second budget and scoped disposal. Copy scalars/full ref identities, never borrowed views or native addresses. There is no generated invocation ID: PRE/POST sequence alone must not become a guessed pairing under nested callbacks. Own factory calls bypass own hooks, so child fragments must be marked from their actual returned refs.

Once timing establishes an unambiguous seam, Items can own armed weapon and projectile records keyed by genuine full refs. Dropping/picking up the same weapon retains its entitlement; only its proven throw consumes it. Detonation matches the retained projectile, including valid full identity before index reuse. Capture the actual thrower, never the purchaser or a successor in the old slot. Preserve fragment recipes and existing reset cleanup.

This read-only source audit performed no native observation or implementation. Add the bounded observer and capture receiving-client timing evidence before claiming transfer behavior. The framework API is available; native ordering is the remaining measurement.
