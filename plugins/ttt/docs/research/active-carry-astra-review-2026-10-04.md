## Ranked, falsifiable hypotheses

Ranking prioritizes diagnostic value and source evidence, not an asserted probability distribution.

1. **The observed state is active despite no human action.** Confirmed current observation has eight moving bots. Core runs tickInteract, effects, DNA, HUD, weapon effects, Economy, Special and once-per-second reconcile while InProgress (`plugin.ts:626–650`), plus communication/other handlers. Body interaction scans inputs and native actor state even without a person pressing a key (`bodies/src/interact.ts:178`); changes from bot combat can trigger nested ordered domain handlers, corpses and natural restarts. Test: correlate slow frame IDs with state, bot count, damage/death/deal events and feature elapsed time. This explains why work persists; it does not yet attribute individual spikes.
2. **Periodic work in true Waiting causes modest spikes or periodic allocation pressure.** The two-second native roster pass is the clearest periodic burst; Reports and warmup reads are the clearest continuous work. Test: record whether roster retry fired in each slow frame, its duration and native probe count, plus Reports and warmup scope timings. Lack of overlap or cheap scopes rejects this as the spike cause. Do not remove roster reconciliation: bots/lifecycle gaps depend on it.
3. **Framework POST work or another loaded component dominates.** All 25 loaded plugins reported by staging, including the fourteen stock plugins, must be inventoried by actual callback ownership rather than assumed inert. `F/core/src/ffi.rs:92–97` runs frame dispatch, async drain, callbacks, queued TopMenu and loader processing. `v8host.rs:5453` snapshots frame handlers and enters contexts even for handlers that return immediately. `frame_async_drain:5804` processes timers/completions and surface retries; six empty sources terminate polling (`5933–5940`), then a microtask checkpoint runs (`5955`). Loader schedules periodic worker work every 64 drains (`loader.rs:1431`), and handles results/admission on the main thread. These are real seams, not proven expensive operations. Stock plugin sources expose relatively few direct frame subscriptions (zones edit polling at `plugins/zones/src/plugin.ts:344`); engine package/UI helpers can also register callbacks, so text-searching owner files is insufficient. Test callback owner counts, loader result counts, async/timer queue/delivery counts and inclusive/exclusive POST timing.
4. **Allocation/GC amplifies otherwise small recurring work.** Reports empty arrays, fixed wire copies and frame-handler snapshots remain. Metadata trees no longer clone per call on103. V8 GC or allocator pressure is plausible but unmeasured; allocation volume alone does not identify pauses. Test timestamped GC start/end and heap size/allocated bytes together with slow frame and bridge counts. Do not force GC or add per-call console output in the measurement arm.
5. **Engine/map/native operation or host descheduling.** Zero players does not halt map entities, physics, networking or the server thread. Wall time may include CPU quota throttling, preemption, I/O or lock waiting. Framework async facilities contain mutex-protected queues (e.g. F/core/src/ws.rs:567), but merely finding a mutex proves neither contention nor a large lock hold. TTT/interop registries are thread-local RefCells, not contended game-thread mutexes. Test same-window process/thread CPU versus elapsed, cgroup cpu.stat throttle deltas, scheduler/runqueue/context-switch data and CPU pressure; use a stack sample when a stall is observed. If all TTT/framework scopes are small and the native report is large, investigate engine/host rather than deleting gameplay fences.
