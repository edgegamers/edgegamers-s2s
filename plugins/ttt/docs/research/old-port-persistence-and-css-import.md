# Old-port persistence and CSS import

Source research, October 2, 2026. Baselines: old port `bd2c382`, edgegamers/TTT `80716fb`, stock s2script `be0a3e3` (SDK0.27.1). This supports the separate MySQL/player-data deliverable; it does not change the API-upgrade gameplay baseline. No deployment, database, export or importer was tested.

## What the old port retains

Karma uses a slot array and SteamID map. Writes round the proposed value, dispatch the cancelable/rewriteable karma event, then store its accepted result. Values are deliberately **unclamped**, including below0 and above100. Disconnect settles pending karma without redispatching that event. Bench rounds and warning timestamps also survive reconnect through SteamID maps. These are module-memory lifetimes: `resetRound()` does not clear those maps, despite a comment describing map lifetime. [Karma storage/write](https://github.com/GabeHirakawa/s2s-ttt-port/blob/bd2c38273c57fac2356982c64b5329087fc147f5/src/karma/karma.ts#L35-L135), [disconnect/reset](https://github.com/GabeHirakawa/s2s-ttt-port/blob/bd2c38273c57fac2356982c64b5329087fc147f5/src/karma/karma.ts#L193-L269).

Shop wallets, ownership and counts reset at Finished and teardown. Slay debt, guilty escalation and reports explicitly clear on map/unload. Logs retain eight rounds in memory. None is a TTT-owned durable database. The old port did not implement CSS Stats upload. [Shop reset](https://github.com/GabeHirakawa/s2s-ttt-port/blob/bd2c38273c57fac2356982c64b5329087fc147f5/src/shop/shop.ts#L165), [teardown](https://github.com/GabeHirakawa/s2s-ttt-port/blob/bd2c38273c57fac2356982c64b5329087fc147f5/src/core/teardown.ts#L79-L90), [log retention](https://github.com/GabeHirakawa/s2s-ttt-port/blob/bd2c38273c57fac2356982c64b5329087fc147f5/src/game/logger.ts#L55-L85), [Stats omission](https://github.com/GabeHirakawa/s2s-ttt-port/blob/bd2c38273c57fac2356982c64b5329087fc147f5/README.md#L163-L171).

Bans are an exception: low-karma and admin RDM paths call framework `Bans.add`. Stock Bans updates the host cache and attempts `bans.json` persistence; its void result and immediate cache read do **not** acknowledge a durable write. Preserve that backing and enforcement integration. [Low-karma call](https://github.com/GabeHirakawa/s2s-ttt-port/blob/bd2c38273c57fac2356982c64b5329087fc147f5/src/karma/karma.ts#L395-L418), [RDM call](https://github.com/GabeHirakawa/s2s-ttt-port/blob/bd2c38273c57fac2356982c64b5329087fc147f5/src/plugin.ts#L596), [stock contract](https://github.com/s2script/s2script/blob/be0a3e33041e921ec113203d4e14a22c996deab7/packages/sdk/bans.d.ts#L40-L53).

## CSS source and export records

Current CSS registers memory-only `KarmaStorageKV`; `KarmaStorageAPI` exists but is unregistered. Historical CSS registered the HTTP karma provider. Neither a `karma.db` connection-string default nor the SQLite package reference proves an actual database/schema. [Current registration](https://github.com/edgegamers/TTT/blob/80716fba705a42ea60bfae0095b5a222e9eba7d1/TTT/Karma/KarmaServiceCollection.cs#L7-L12), [memory implementation](https://github.com/edgegamers/TTT/blob/80716fba705a42ea60bfae0095b5a222e9eba7d1/TTT/Karma/KarmaStorageKV.cs#L10-L35), [historical provider](https://github.com/edgegamers/TTT/blob/bcac8361b0f1968cce3610e02bf1fd1ba01469f9/TTT/Karma/KarmaStorage.cs#L21-L44).

## Compatible remaining work

Stock SDK already supports asynchronous MySQL queries/execute. Explicitly validate the configured MySQL connection: absent names fall back to SQLite. Preserve ordered accepted karma writes, unclamped values and guarded asynchronous hydration. Reuse reviewed transport/journal/receipt mechanics where compatible; do not carry over older capped-karma or durable-slay policy. [API](https://github.com/s2script/s2script/blob/be0a3e33041e921ec113203d4e14a22c996deab7/packages/sdk/db.d.ts#L49-L79), [runtime resolution](https://github.com/s2script/s2script/blob/be0a3e33041e921ec113203d4e14a22c996deab7/core/js/prelude.js#L1599-L1672).

Identify the deployed CSS revision/provider, backend revision/schema and immutable export before implementing its extraction adapter. Build an export-based importer against verified fields: dry-run, source checksum/provenance, exact string identities, conflicts, bounded transactions, checkpoints and idempotent reruns. Preserve unknown fields and nulls; do not invent missing records, sum summaries with their history, derive wallets, or replay imported history into bans/slays. MySQL/migration remains separate from gameplay and does not require native changes.
