# Astra source review — entity lifecycle fanout

The proposed cause “each glow create/spawn enters every loaded plugin context even without a handler” is refuted by framework commit 10379521277a9100117104baa4f27b2012af62af. No patch adding a missing empty-listener gate is indicated.

The actual route is shim/src/entity_listener.cpp:25–26,62 → core/src/ffi.rs:294 → core/src/entity.rs:1320 → core/src/dispatch.rs:347. Entity replay builds only exact `<kind>\0<class>` and `<kind>\0*` subscription snapshots. Channels::snapshot (core/src/channels.rs:60) performs a keyed lookup, returning an empty vector for an absent channel. It does not enumerate loaded plugins. fan_out_inner enters its scalar dispatch epoch scope, then checks snap.is_empty at lines358–361 and returns Delivered before nest lookup, CallbackScope, HOST/isolate borrow or context entry. Empty snapshots also do not request a deferred replay.

For nonempty snapshots, fan_out_call_subscribers (core/src/dispatch.rs:244) loops only the snapshot's named owners. Per-subscriber owner/generation liveness and context clone precede argument creation/callback invocation. Legacy module initialization in core/js/prelude.js:2284–2286 subscribes wildcard entity handlers only if the corresponding OnEntityCreated/Spawned/Destroyed export is a function. There is no automatic no-op subscription per plugin.

Matching subscribers can run synchronously: s2_entity_create (core/src/entity.rs:801) and spawn_kv (line1044) wrap outbound engine calls in nest::with_outbound. fan_out_inner routes a nonempty snapshot through the current nested CallbackScope when permitted. Stale shim comments that every plugin-originated create necessarily defers JS must not replace this current control flow. Whether any loaded stock plugin has an actual matching `prop_dynamic` or wildcard callback is not measured by this source review; subscriber count, not loaded-plugin count, determines that fanout.

The TTT modular source's explicit lifecycle subscription is scope.entities.onCreate("player",...) in plugins/core/src/plugin.ts:545. The old port has the same player-class subscription in src/plugin.ts:469. It does not match prop_dynamic. This is source inventory, not a live subscription census.

There remains unconditional synchronous native bookkeeping. ffi.rs:308–315 feeds entity_live before dispatch, even for an empty listener snapshot. entity_live.rs:23–43 updates the liveness table and calls surface_leases::prune_dead plus shared_entity_switch::prune_dead on both create and spawn. That work has no missing listener guard by design: the identity authority must update before createEntity can adopt a returned handle, and callbacks must not resurrect or write stale entities. Native registry pruning cost and actual registry population remain unmeasured. The framework agent is separately tracing this path; no blanket skip of the liveness feed is safe.

The four createEntity calls measured at 12 ms total encompass native creation/spawn plus synchronous bookkeeping and any real matching callbacks, along with binding/keyvalue work. They cannot identify any one contributor from source alone. They do not support a 25-context-versus-one fanout explanation. If no source-proven redundant operation emerges, fixed native spans around existing create, keyvalue construction, DispatchSpawn and lifecycle bookkeeping would discriminate actual cost while retaining all current identity/dispatch/exception semantics.

No source edits, tests, builds, server actions or native calls were performed for this source-only review.
